Періодичне отримання даних

Скрипт scripts/http_polling.py опитує /api/weather/current кожні 60 секунд, перевіряє наявність основних полів, використовує тайм-аут HTTP-запиту та записує отримані значення у файл http_weather_history.csv.

Запуск:

python ".\scripts\http_polling.py"

Зупинка — Ctrl + C.

CSV-файл створюється автоматично після успішного отримання даних. Він призначений для локальної історії та не додається до Git-репозиторію.

MQTT

Скрипт scripts/mqtt_weather_station.py призначений для передавання показників метеостанції через MQTT.

Основні теми:

weather-station/temperature

weather-station/humidity

weather-station/pressure

weather-station/rssi

weather-station/status

У конфігурації передбачені QoS 1, retained-повідомлення та Last Will для повідомлення про втрату з'єднання. Для повноцінної перевірки необхідні запущений брокер Mosquitto та коректні облікові дані. Під час попередньої перевірки MQTT-емулятор отримував помилку авторизації, тому успішний обмін MQTT із брокером ще не підтверджено.

BLE

BLE представлено програмною емуляцією. Вона дозволяє демонструвати температуру, рівень сигналу RSSI та заряд батареї, але не є скануванням реального Bluetooth-пристрою. Фізичний BLE-адаптер і справжній GATT-обмін не перевірялися.

Конфігурація OpenHAB

У каталозі openhab_config/conf зберігаються конфігураційні файли Items, Things та Rules для подальшого налаштування системи.

Файли цієї практичної роботи зберігаються окремо від робочої конфігурації OpenHAB. Правила та повний обмін даними між HTTP API, MQTT, BLE-емулятором і Items ще потребують перевірки безпосередньо в OpenHAB.

Автоматичні тести

Запуск тестів із кореневої папки практичної роботи:

python -m unittest discover -s tests -v

Під час останнього запуску успішно пройшли 6 тестів:

4 тести HTTP API: погода, статус, перелік пристроїв і BLE-емулятор;

2 тести HTTP polling: отримання даних і запис CSV.

Результат останнього запуску: Ran 6 tests ... OK.

Обмеження

Наявність емулятора не означає, що відповідний протокол уже повністю інтегрований в OpenHAB. MQTT-авторизацію, виконання Rules DSL, періодичне оновлення Items через HTTP та реальне BLE-з'єднання потрібно перевірити окремо.

Висновок

У межах практичної роботи створено HTTP API, скрипт періодичного отримання погодних даних, CSV-історію, MQTT-емулятор і програмну емуляцію BLE-сенсора. Автоматичні тести підтверджують працездатність HTTP API та базових функцій збереження історії. Наступний етап — завершення інтеграції протоколів і перевірка правил автоматизації в OpenHAB.
