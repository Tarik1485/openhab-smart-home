Практична робота 3.3

Захист комунікацій в IoT

Дисципліна: IoT та SMART-технології
Тема: Протоколи зв'язку в IoT. Захист комунікацій
Мета: Ознайомитися з механізмами криптографічного захисту IoT-пристроїв, сертифікатами X.509, цифровими підписами та виявленням повторних повідомлень.

1. Використані засоби

OpenSSL 4.0.3.

Python 3.12.7.

RSA та X.509.

HMAC-SHA256.

Python unittest.

2. Інфраструктура відкритих ключів (PKI)

Створено кореневий центр сертифікації Root CA з ключем RSA 4096 біт. Створено проміжний центр Intermediate CA з ключем RSA 3072 біт. Проміжний центр підписав сертифікат IoT-пристрою sensor-01.

Ланцюжок довіри перевірено командою OpenSSL. Результат: certs/sensor-01.crt: OK.

Сертифікат пристрою призначений для автентифікації TLS-клієнта.

3. Захист повідомлень IoT

Розроблено Python-програму scripts/secure_messaging.py, яка демонструє:

перевірку HMAC-SHA256;

виявлення змінених повідомлень;

перевірку часу повідомлення;

виявлення повторного надсилання за nonce;

журналювання подій безпеки.

У тестовому запуску справжнє повідомлення було прийнято, повторне та змінене — відхилені.

4. Перевірка цілісності прошивки

Створено демонстраційний файл прошивки firmware/firmware-v1.bin. Для нього створено RSA-ключі та цифровий підпис.

Для незміненого файла OpenSSL повернув Verified OK. Після модифікації файла перевірка завершилася Verification failure, що підтверджує виявлення зміни вмісту.

5. Автоматичне тестування

Виконано команду:

python -m unittest discover -s tests -v

Результат: 3 тести пройшли успішно.

Перевірено:

Прийняття правильного повідомлення.

Відхилення повторного повідомлення.

Відхилення зміненого повідомлення.

6. Межі реалізації

Робота є програмною демонстрацією на локальному комп'ютері. Реальне підключення ESP32, MQTT-брокер із TLS 1.3/mTLS, апаратний Secure Boot, HSM, VPN/IPsec, OCSP та повноцінна CRL-інфраструктура не розгорталися й не тестувалися. Ці механізми не слід вважати реалізованими лише на підставі наведених демонстрацій.

Ключі зберігаються у локальній папці private/, захищеній від випадкового включення до Git через .gitignore. Для виробничого застосування необхідне спеціалізоване захищене зберігання ключів і додаткові заходи безпеки.

7. Висновок

Під час роботи створено і перевірено ієрархію сертифікатів X.509, реалізовано навчальну модель захисту повідомлень HMAC-SHA256 та механізм виявлення повторних повідомлень. Також перевірено цифровий підпис тестової прошивки та продемонстровано виявлення її модифікації. Автоматичні тести завершилися успішно.
